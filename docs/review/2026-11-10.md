# Review of 10 November 2026: findings not acted on

A review of the core asked whether Corbie has features it does not need, code that is hard to follow, and fields a definition must write for no reason. What was changed is in `manual/pages/changes.txt` under "After 0.22.0" and in the commits. This file lists what was found and left, with the reason, so that each can be picked up later.

## Fields a definition must write

- **A reply to `event.from` needs `send:**`.** A machine that only answers its sender must allow a send to any location. Allowing the reply without it would be an exception in the send check. Two files in Rook write `send:**` for this.
- **A child run needs `receive: []` to refuse events from its tree.** Rook writes it 20 times, in 10 files, on purpose, so that a router takes events only from its listener. Changing the default would make every send inside a tree need a `receive:` line.
- **A flow handles a stage's failure by which names an expression reads.** Reading `stages.<name>.error` or the output of a stage with `each:` is what stops the failure from ending the flow. A field on the stage would say it plainly, and would add a field.
- **`approve:` and `call:` each have two forms, and `each:` has five.** Removing a form breaks definitions and shortens none.

## Features with few users

- **A machine made while running (`machine: ${…}`) and an agent's `list:` tools.** They cost `controller/made.go`, sixteen constraints, and most of the list in `specs/permission.md` of what Corbie does not defend against. No file in Rook, the UI, the console or the house was checked for them.
- **`limits: { runs }` at a transient location.** No file in Rook, the UI, the console or the house writes it. It costs one rule and reuses the key files of keyed locations. It is the only cap on how many runs a caller starts at a location.
- **`read:`.** Kept. The console is a client of its own with a token on a wall screen, and `read:` lets it read runs without being the tree's client, which could submit and cancel. A client `read:` lists reads the tickets of those runs, so it can answer them.

## Code that is hard to read

- **`instance.Ask` is one struct for thirteen kinds.** The kind `event` covers four actions, told apart by which fields are set: a send job, a send to an address, an event to a child or a parent, and an event written only in the record. `Attempt` holds an emit's index in one of them. Giving each action its own kind changes the record that the UI and Rook's tests read.
- **The parser checks its own tables.** `Fields.named` and `Fields.read` in `machine/parse.go` report "a fault in Corbie" when the reader and the shape tables disagree. The checks exist because each field is described twice: in the table the UI shows and in the code that reads it. Reading fields from the table would remove them, and is a redesign.
- **The walk over a definition's expressions is written three times.** The first reading of the code found this, and it was not looked at again.

## Commands and the gateway

- **`corbie controller cancel` waits for no receipt.** It refuses a run that has ended, and otherwise exits 0 once its message is written. `corbie run cancel` waits.
- **The gateway's `POST /runs` has two request shapes.** It takes JSON, or a form when the input has a file. One shape would be simpler for a caller.

## Data that outlives a run

`handover:` was removed. Corbie has no place in the store for data that outlives a run, and none was added: data in the store that belongs to no run has nothing that removes it. A machine that must keep data writes a file with `fs.write:`. That file is on the runner's disk, so such a machine needs a runner that always has the same disk.

`fs.write` writes over a file in place. A script that must not lose the old contents writes a second file and moves it over the first with `fs.move`.

## The other repositories

- **Rook's worked example** (`test/testdata/grouse/`) restarts virtual computers on a hypervisor. The author has not said whether that content comes from their work, as the example's old name did.
- **The console** requires Corbie 0.21.0. It was not built or tested against this version.
- **The house's ceiling** (`deploy/ceiling.sh`) is not run by the house's tests, which use a ceiling of `all`.
