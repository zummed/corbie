A tree of machines: one command records a directory of machines, each at its location, and starts the ones that always run.

    # schedules/evening.yaml
    statechart: evening
    lifetime: singleton
    initial: waiting
    states:
      waiting:
        timers: { due: "18:00 Europe/London" }
        on: { due: working }
      working:
        job: { script: ./work.js }
        on:
          done: waiting
          failed: waiting

    // schedules/work.js
    log("the evening work")

    corbie init --ceiling all
    corbie start &
    corbie run submit schedules
      /schedules/evening   singleton   started <id>
    corbie run show <id>

Submit again after a change: nothing else watches the files.

Reference
---------

  corbie run submit <directory> --at <prefix>   records the directory as a tree at the prefix
  corbie test <directory>...                    reads every machine, and starts nothing

It reads every *.yaml in the directory and below it as a machine, but for .git and what .corbieignore lists. A machine's location is its path under the prefix, without .yaml.

  schedules/evening.yaml at /schedules   /schedules/evening
  house/devices/boiler.yaml at /home     /home/devices/boiler

.corbieignore, at the top of the directory, lists what is no machine, one path a line, from the directory:

  shared/       a directory, and everything below it
  notes.yaml    one file
  # a note      passed over, as an empty line is

- A listed file has no location: nothing runs there, and nothing can be sent to it.
- A machine still includes a listed file, runs it with machine:, and reads it with files:.
- A *.yaml that is no machine, such as one in .github/, is a problem until it is listed.

A file of one line places a listed machine at its own location. It takes the type, the name and every field from the listed file:

    # chat/.corbieignore
    shared/

    # chat/shared/post.yaml
    flow: post
    stages:
      say: { job: { script: ./post.js } }
    output: ${stages.say.output}

    // chat/shared/post.js
    return "posted"

    # chat/team/post.yaml
    include: shared/post.yaml

    corbie test chat
      chat/team/post.yaml  ok
      chat/shared/         listed

- A field the placed file writes wins over the listed file's, such as receive:.
- Two files that place one machine are two locations, and their runs have one name.

`lifetime:` says how a location's runs start:

  singleton             the submit starts its one run, when none is running
  keyed                 a send to a key with no running run starts one
  transient, default    corbie run submit <location> starts one

What the submit does at a location:

  a new singleton                    starts its run
  a changed file, update: restart    cancels its runs, and starts a singleton again
  a changed file, update: drain      leaves its runs on the definition they started with
  a file gone from the tree          cancels every run at its location
  a file with a problem              reports it, and the location keeps what was recorded before

- `--at` is / and the directory's name by default. A tree is not inside or above another, and / is never a tree.
- A tree belongs to the client that first submitted it. Only that client reads and cancels the runs at its locations.
- The client's ceiling needs an at: entry for the prefix. `corbie init` gives its client at:/**.
- drain is the default for keyed and transient files. A singleton always restarts, once its old run and that run's children have ended.
- A file beside a directory of the same name, as boiler.yaml beside boiler/, is refused with the files below it: a location has nothing below it. The rest of the tree is recorded.
- A singleton is given no input, so one whose input: needs a value is refused. A run reads the directory's absolute path as ${run.context}, its location as ${run.location}, and the tree's prefix as ${run.tree}.
- The submit prints the secrets and values the files use that are not set at their locations or above.

`corbie test <directory>` checks each send and call whose `at:` is written out and is in the tree, as the controller would:

  the location has a file         a location with none is printed, which fails nothing
  the lifetime fits               { at } to a singleton, { at, key } to keyed, a call to transient
  receive: lists the sender       read for the event's name, or for a call
  the event is not the file's     such as the name of its timer
  the sender holds send:          in its own allow: and deny:; a list with ${…} in it is left out

Values, secrets and ceilings are on the controller, so the test does not check them.

To have a machine come back when it ends, run it as a job with restart:. `corbie manual definitions` gives the fields.

    # keep.yaml
    flow: keep
    stages:
      hearing:
        job:
          machine: ./hear.yaml
          restart: { after: always, limit: 1, delay: 1s }

    # hear.yaml
    flow: hear
    stages:
      one: { job: { script: ./one.js } }

    // one.js
    return 1
