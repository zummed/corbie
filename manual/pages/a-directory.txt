A tree of machines: one command records a directory of machines, each at its location, and starts the ones that always run.

    # schedules/evening.yaml
    statechart: evening
    lifetime: singleton
    initial: waiting
    states:
      waiting:
        timers: { due: "18:00 Europe/London" }
        on: { due: working }
      working:
        job: { script: ./work.js }
        on:
          done: waiting
          failed: waiting

    // schedules/work.js
    log("the evening work")

    corbie init --ceiling all
    corbie start &
    corbie run submit schedules
      /schedules/evening   singleton   started <id>
    corbie run show <id>

Submit again after a change: nothing else watches the files.

Reference
---------

  corbie run submit <directory> --at <prefix>   records the directory as a tree at the prefix
  corbie test <directory>...                    reads every machine, and starts nothing

It reads every *.yaml in the directory and below it, but for .git. A file whose first key gives a type of machine has a location: its path under the prefix, without .yaml. Any other file is a piece, which a machine reads by including it.

  schedules/evening.yaml at /schedules   /schedules/evening
  house/devices/boiler.yaml at /home     /home/devices/boiler

`lifetime:` says how a location's runs start:

  singleton             the submit starts its one run, when none is running
  keyed                 a send to a key with no running run starts one
  transient, default    corbie run submit <location> starts one

What the submit does at a location:

  a new singleton                    starts its run
  a changed file, update: restart    cancels its runs, and starts a singleton again
  a changed file, update: drain      leaves its runs on the definition they started with
  a file gone from the tree          cancels every run at its location
  a file with a problem              reports it, and the location keeps what was recorded before

- `--at` is / and the directory's name by default. A tree is not inside or above another, and / is never a tree.
- A tree belongs to the client that first submitted it. Only that client reads and cancels the runs at its locations.
- The client's ceiling needs an at: entry for the prefix. `corbie init` gives its client at:/**.
- drain is the default for keyed and transient files. A singleton always restarts, once its old run and that run's children have ended.
- A file beside a directory of the same name, as boiler.yaml beside boiler/, is refused with the files below it: a location has nothing below it. The rest of the tree is recorded.
- A singleton is given no input, so one whose input: needs a value is refused. A run reads the directory's absolute path as ${run.context}, and its location as ${run.location}.
- The submit prints the secrets and values the files use that are not set at their locations or above.

To have a machine come back when it ends, run it as a job with restart:. `corbie manual definitions` gives the fields.

    # keep.yaml
    flow: keep
    stages:
      hearing:
        job:
          machine: ./hear.yaml
          restart: { when: always, limit: 1, delay: 1s }

    # hear.yaml
    flow: hear
    stages:
      one: { job: { script: ./one.js } }

    // one.js
    return 1
