Using secrets: a job sends a secret to one named place, and its script never reads the value.

A secret is a value such as an API token.

- The controller keeps the secret in the store, encrypted so that only the
  controller can read it.
- A job's `allow:` list names the secret and the one place it can go:
  `secret:GITHUB_TOKEN@net:api.github.com`.
- The controller puts the value in that job, which is encrypted for its runner.
- The script gets a handle, never the value.

What Corbie does depends on where the script sends the handle.

- When the script sends the handle to `api.github.com`, Corbie sends the value
  in its place.
- When the script sends the handle to any other host, Corbie refuses, and the
  job fails with status `denied`.
- When a reply contains the value, Corbie replaces it with
  `[secret GITHUB_TOKEN]`.

Set a secret
------------

  corbie controller secret set GITHUB_TOKEN        kept by the controller, for every run
  corbie submit flow.yaml --secret GITHUB_TOKEN    sent with a run, for it and its child runs

Each reads the value from the environment variable `GITHUB_TOKEN`. The first
runs on the controller's computer, and reads standard input when the variable
is not set. A secret sent with a run replaces a controller secret of the same
name, and `corbie test` takes `--secret`.

A job that names a secret set in neither way fails before its script is sent
to a runner: `the secret GITHUB_TOKEN is not set`.

Other places a secret can go
----------------------------

  secret:DEPLOY_TOKEN@exec:deploy                    to that program
  secret:APP_KEY@fs.write:/etc/app/key               into that file
  secret:HOME_TOKEN@net.unencrypted:10.0.30.8:8123   to that host, encrypted or not
  secret:TG_BOT@*                                    anywhere the job is allowed

A secret bound with `net:` is sent only over an encrypted connection. For a
device that accepts only plain HTTP, write `net.unencrypted`: anyone on the
network path can then read the secret.

Use it in a script
------------------

    allow: [net:api.github.com, "secret:GITHUB_TOKEN@net:api.github.com"]

    const gh = secrets.get("GITHUB_TOKEN")
    const me = http.get("https://api.github.com/user", {
      headers: { Authorization: secrets.text`Bearer ${gh}` },
      as: "json",
    })
    return me.body.login                // gives "octocat"

  net:api.github.com   needed too: a secret: entry grants no connection, program or file
  secrets.get          returns the handle
  secrets.text         joins text and handles into a new handle

Each plugin's page lists where its calls take a handle, such as a header, a
URL, a body, a program's argument or a file. A script cannot convert a handle
to text, compare it, measure it, return it or emit it.

A script allowed to connect to a secret's destination can learn the secret
from the server there: see `corbie manual limits`.
