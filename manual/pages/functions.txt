Functions: the controller, the runners and the gateway run as AWS Lambda functions on an S3 bucket, so nothing runs while there is no work.

What calls a function
---------------------

  a file written to the controller's inbox   the controller's function
  a file written to a runner's inbox         that runner's function
  a schedule, once a minute                  the controller's function, for timers

A function handles everything that is waiting, then exits. A timer can fire up
to a minute late. AWS Lambda with S3 is the only serverless host supported.

Create the controller, the runner and their policies
----------------------------------------------------

  corbie init --store 's3://my-bucket/main?region=eu-west-2' --ceiling exec --name cloud
  corbie controller policy cloud-controller > controller-policy.json
  corbie controller policy cloud-runner     > runner-policy.json

Run these on your own computer, with an access key that can write to the
bucket (`corbie manual bucket`). Give each function its own IAM role, with the
policy printed for it.

Build each function's package
-----------------------------

  package/bootstrap             the start script below
  package/corbie                the binary, built for the host
  package/config/controller/…   the controller's config (config/runner/… for a runner)

  #!/bin/sh
  cd "$LAMBDA_TASK_ROOT" && exec ./corbie start $CORBIE_SERVE --config "$LAMBDA_TASK_ROOT/config"

  runtime       provided.al2023
  handler       bootstrap
  CORBIE_SERVE  controller on one function, "runner --jobs 4" on the other
  timeout       for a runner, its longest job's timeout plus 30 seconds;
                for a controller, at least 30 seconds

Each step of a machine made while running, and each step after the first of
an agent with a `list:` tool, starts a process, up to four at a time, which
takes about 15 ms and may hold 1 GiB of memory. A function with less memory is
stopped by Lambda at that point, and the step's machine fails.

A function's code can be replaced while runs are in progress.

Keep the private keys in a bucket
---------------------------------

By default each package holds its party's private keys, in
`config/<kind>/identity`. With `--identity`, `init` writes them to a bucket,
and each package holds their address.

  corbie init --store 's3://my-bucket/main?region=eu-west-2' --identity 's3://my-keys/cloud?region=eu-west-2' --ceiling exec --name cloud

  the objects   cloud/controller/identity, cloud/runner/identity, cloud/client/identity
  the package   config/controller/identity-address, and no private key
  the policy    `corbie controller policy` allows each party to read its own object

A function reads its keys each time it starts. Whoever may read an object has
that party's keys, and Corbie does not check the key bucket's policy. To
replace the keys, run `init` with a new config, a new `--identity` path and a
new store.

Have the bucket call each function
----------------------------------

The inbox prefixes are `main/cloud-controller/inbox/` and
`main/cloud-runner/inbox/`. Permit the bucket to call the functions.

  aws lambda add-permission --function-name corbie-controller --statement-id bucket \
      --action lambda:InvokeFunction --principal s3.amazonaws.com \
      --source-arn arn:aws:s3:::my-bucket --source-account <account>
  aws lambda add-permission --function-name corbie-runner --statement-id bucket \
      --action lambda:InvokeFunction --principal s3.amazonaws.com \
      --source-arn arn:aws:s3:::my-bucket --source-account <account>

The next command replaces the bucket's whole notification configuration, so
include any that it already has.

  aws s3api put-bucket-notification-configuration --bucket my-bucket \
      --notification-configuration '{"LambdaFunctionConfigurations": [
    {"Id": "controller-inbox", "Events": ["s3:ObjectCreated:*"],
     "LambdaFunctionArn": "arn:aws:lambda:eu-west-2:<account>:function:corbie-controller",
     "Filter": {"Key": {"FilterRules": [{"Name": "prefix", "Value": "main/cloud-controller/inbox/"}]}}},
    {"Id": "runner-inbox", "Events": ["s3:ObjectCreated:*"],
     "LambdaFunctionArn": "arn:aws:lambda:eu-west-2:<account>:function:corbie-runner",
     "Filter": {"Key": {"FilterRules": [{"Name": "prefix", "Value": "main/cloud-runner/inbox/"}]}}}]}'

The bucket can take five minutes to begin calling after this command.

Call the controller once a minute
---------------------------------

  aws events put-rule --name corbie-minute --schedule-expression 'rate(1 minute)'
  aws lambda add-permission --function-name corbie-controller --statement-id minute \
      --action lambda:InvokeFunction --principal events.amazonaws.com \
      --source-arn arn:aws:events:eu-west-2:<account>:rule/corbie-minute
  aws events put-targets --rule corbie-minute \
      --targets Id=controller,Arn=arn:aws:lambda:eu-west-2:<account>:function:corbie-controller

Check it
--------

Run these where you ran `init`.

  corbie check
  corbie run submit hello.js
  corbie run start /hello --wait

If a call is missing, the check's `late` or `never` line names it. In the
first five minutes after the bucket was told to call, wait and check again.

  the bucket does not call the controller   every step is up to a minute late
  the bucket does not call a runner         no job is taken
  nothing calls once a minute               no timer or timeout is noticed

The bucket refuses a function whose role has the wrong policy. The error is in
the function's log.

A job must fit in one call
--------------------------

A runner takes a job only if the job's timeout plus 20 seconds fits in the
time the call has left. A job that can never fit fails at once. The default
job timeout is five minutes, which needs a function timeout of 330 seconds.

Copies of a function
--------------------

The host starts another copy of a function when work arrives while one is
busy. Every copy is the same controller or runner, so each job runs once and
each step is written once. One copy of a runner runs `--jobs` jobs at a time.

Corbie needs no limit on copies. A limit only saves the cost of repeated work
when many messages arrive together.

  aws lambda put-function-concurrency --function-name corbie-controller \
      --reserved-concurrent-executions <copies>

A throttled call is not lost: the next call handles everything in the inbox.
A limit on a runner's function caps the jobs running at once at its copies
times `--jobs`. A job that waits past its timeout fails as a timeout.

The gateway as a function
-------------------------

A gateway is a function of its own, which Lambda calls once for each HTTP
request to the function's URL (`corbie manual gateway`).

  package/bootstrap          the same start script
  package/corbie             the binary
  package/config/client/…    the client's config
  package/tokens             the token file: a line for each token

  CORBIE_SERVE  gateway --token-file tokens
  timeout       the longest a request may wait, plus ten seconds
  role          the policy `corbie controller policy cloud-client` prints

Give the function a URL that sends each answer on as it is written, and
permit calls to it. The gateway's token is what a caller must show.

  aws lambda create-function-url-config --function-name corbie-gateway \
      --auth-type NONE --invoke-mode RESPONSE_STREAM
  aws lambda add-permission --function-name corbie-gateway --statement-id url \
      --action lambda:InvokeFunctionUrl --principal '*' \
      --function-url-auth-type NONE
  aws lambda add-permission --function-name corbie-gateway \
      --statement-id url-invoke --action lambda:InvokeFunction \
      --principal '*' --invoked-via-function-url

The first command prints the URL, which is `https`. Check it with the token.

  curl -H "Authorization: Bearer $TOKEN" https://<id>.lambda-url.eu-west-2.on.aws/client
    {"client":"cloud-client"}

- A request's time ends ten seconds before the function's timeout. `?wait`
  then answers with the run as it stands, and a `?watch` stream closes.
- A stream runs until then, also after its caller has left, and Lambda bills
  that time.
- Lambda refuses a request over 6 MB. A submit of 4 MB of files was taken, and
  one of 5 MB was answered 413.
- An answer may be larger, up to Lambda's 200 MB. A file of 30 MB of a run's
  result was sent in 25 seconds. It must be sent within the request's time.
- With no token file and no OIDC issuer the function does not start. Its log
  says why.

One function with every role
----------------------------

`corbie up` in a function runs the controller, the runner and the gateway in
that one process, with the store in the function's temporary directory. It
needs no bucket and no `corbie init`.

  package/bootstrap    the start script below
  package/corbie       the binary
  package/project/…    the directory of machines
  package/tokens       the token file

  #!/bin/sh
  cd "$LAMBDA_TASK_ROOT" && exec ./corbie up --in project gateway --token-file tokens

Give the function a URL as for a gateway. `POST /runs?wait` starts a run and
is answered with it (`corbie manual routes`).

- A run's blob is read in a later request, which may go to another copy. A
  run there gives what its caller needs as values in its output.
- Each copy of the function has its own store. A request for a run that
  another copy recorded is answered 404, and a run started at a tree that
  another copy recorded fails with `nothing is recorded at`.
- The process runs only while a request is being answered.
- A copy's store is deleted when Lambda discards the copy.
- `--store` is refused: a bucket is used with the functions above.

Use it for a run that ends within the request that started it. A run that
goes on after its request needs the bucket and the functions above.

Computers beside functions
--------------------------

A controller, runner or client can also run on a computer
(`corbie manual bucket`). Give a runner that is kept for a program, a GPU or a
private network its own tags, and name them in the `tags:` of the jobs that
need it.
